# RYLUX 2.5.50 — 背包物品详情浮层关闭修复（RC1）

## 复现日志

2026-11-19 用户设备日志显示：
- 游戏主界面识别成功：地图栏 95.6%、角色头像 93.7%。
- 背包标题识别成功：99.8%。
- 进入大夫商店成功：商店标题 99.8%。
- 背包空格预检识别 26/35 个空格，药瓶保护位置为 [1,2]。
- 装备扫描继续到第 29–34 格，这些格子没有通过装备功力行确认，按保护规则保留。
- 即将选择第 35 格时，脚本抛出：`物品详情仍遮挡背包格子；已停止扫描。`

因此本次不是 Gitee 清单获取、APK 安装或游戏启动失败；CoraFlow 工作流已执行到大夫商店的 35 格扫描阶段。

## 根因定位

`CoraFlowWorkflowRuntime.selectInventorySlot` 在选择下一格前发现上一格物品详情浮层，会尝试点击 `(1200,80)`，再发送 Escape 并复核。

对照仓库内恢复的旧 Lua 脚本 `app/src/main/assets/script_modules/脚本/挂机模式.lua`：
- 装备详情关闭动作 `@@关掉选中物品` 使用坐标 `(1184,638)`。
- 普通物品详情关闭动作 `@@关掉非装备物品` 也使用坐标 `(1184,638)`。

CoraFlow 的 `(1200,80)` 位于画面上方标题区，并非旧脚本使用的物品详情关闭按钮位置。导致关闭动作没有消除详情浮层，后续 Escape 也没有使模板复核通过，最终安全停止扫描。

## RC1 修复

- 新增共享常量 `INVENTORY_DETAIL_CLOSE_X/Y = 1184/638`。
- 统一修正四处详情浮层清理路径：药瓶计数、装备扫描结束清理、扫描下一格前清理、空格预检。
- 关闭动作后等待 400ms 并重新截图复核；若浮层仍存在，再尝试系统返回键并再次复核。
- 若仍检测到详情浮层，继续安全停止，不允许在遮挡状态下误点下一格或出售。
- 新增 `CoraFlowInventoryDetailCloseTest`，防止回退到错误的标题区坐标。
- 不改装备识别阈值、出售策略、药瓶保护规则或 OCR 逻辑。

## 设备验收

1. 覆盖安装，不卸载应用、不清除数据。
2. 进入游戏和大夫商店，运行背包装备扫描。
3. 检查日志是否出现「点击旧版脚本确认的关闭位置（1184,638）」和「上一格物品详情浮层已关闭，继续扫描下一格」。
4. 确认第 29–35 格能在每格详情关闭并复核后继续扫描；不通过功力行的装备仍然保留。
5. 验证出售仍需通过功力行、品质、出售按钮和二次确认，未识别项目不出售。
6. 如果仍失败，提供新的日志，重点查看关闭点击后模板是否仍命中，以及 Escape 后是否仍命中。

本次修复已通过源码静态定位；只有在真实设备上复测后，才能确认 UI 关闭行为已恢复。
